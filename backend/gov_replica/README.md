# gov_replica

Local demonstration replicas of public government portals, generated by the
pipeline in [`../tools`](../tools).

Each replica is an **unofficial local demonstration** built for authorized
development, testing and educational use. None of these directories contains an
official government service, and none of them should be deployed anywhere a
member of the public could mistake it for one.

## Why this exists

The ERP described in `docs/requirements/erp-scope.pdf` has to exchange data with eight
external government systems. The research reports in `docs/research_reports/` establish that
**none of those systems publishes a public API** — every one is paper-based,
CAPTCHA-protected, or behind an authenticated login on a closed network. These
replicas therefore serve two purposes:

1. a faithful reference for the fields, validation rules and workflows the ERP
   must mirror, so a citizen or officer never has to retype data; and
2. a local stand-in for integration development and testing, so ERP work does
   not depend on access to a production government system.

\* the crawl stopped at the configured page limit, so those sites are **not fully explored** — `uidai.gov.in` has 113 in-scope URL(s) still queued, `ecourts.gov.in` has 2331 in-scope URL(s) still queued. Each project's `website_overview.json` states this exactly.

**Visual diff** is the measured mean pixel difference at desktop, banner-aligned
(see each project's `analysis/visual_comparison.json`). Lower is closer.

`eprisons_nic_in` was hand-tuned page by page.
The rest are generated by `tools/bin/build-replica.js` from the captured
analysis. The generator reproduces **fields, option lists, validation rules,
dependent dropdowns and page structure** faithfully, and approximates visual
design from measured colour, type and geometry tokens. It does not redistribute
the originals' illustrations, icons or prose, so on a heavily designed page a
high difference number means the replica looks different **on purpose** — not
that a pixel copy failed.

## Category structure

| Directory | Website category |
|---|---|
| `Aadhaar/` | Aadhaar/UIDAI identity services, enrolment, updates and related official services |
| `CCTNS/` | Crime and Criminal Tracking Network & Systems, police crime-record workflows and related portals |
| `E_Courts/` | eCourts, case status, court listings, cause lists, orders, judgments and court services |
| `E_Forensics/` | Government forensic services, forensic laboratories, forensic case management and evidence workflows |
| `E_Prisons/` | ePrisons, prison/jail administration, inmate management, visitor services and related portals |

A site that fits none of these gets its own clearly named category directory, or
`Unclassified/` when the evidence does not support a confident verdict. Within a
category, every hostname gets its own isolated project directory. Artifacts for
one domain never leave that domain's directory.

## Running one

```bash
cd gov_replica/<Category>/<host>/replica/backend
npm install && npm run seed && npm start
```

Then the tests:

```bash
cd gov_replica/<Category>/<host> && node tests/run-tests.js
```

Each project has its own `README.md` with the full picture: how it was analysed,
what could not be reached, how to run it, and what is deliberately not reproduced.

## Adding another

```bash
cd tools
node bin/gov-replica.js <domain>          # the domain is the only input
node bin/build-replica.js ../gov_replica/<Category>/<host> --port <N>
node bin/compare-replica.js ../gov_replica/<Category>/<host> http://127.0.0.1:<N>
node bin/write-readme.js ../gov_replica/<Category>/<host>
node bin/write-index.js                   # refresh this file
```
